# Build and validation

Building OBI is not just compiling Go. The eBPF C sources under `bpf/` must be compiled to bytecode and wrapped in generated Go bindings before any Go code will compile, and that generation is expected to be reproducible — which is why the canonical path runs it inside a container.

This page covers the workflow a change has to pass through, and which target to reach for.

## TL;DR

- `make verify` is the main validation flow: `prereqs`, `go-mod-tidy`, `lint`, `test`, `license-header-check`.
- `make build` is the full path: `docker-generate` → `verify` → `compile`.
- **Any change to a `.c` file under `bpf/` obliges you to run `make generate` (or `make docker-generate`)** — the checked-in `*_bpfel.go` and `*.o` artifacts are outputs, not sources.
- `make generate` is incremental; `make generate/all` forces everything and is what you want after a clean clone or `git clean`.
- C must be formatted and linted: `make clang-format` and `make clang-tidy`, or install the git hook once with `make install-hooks`.
- Markdown-only changes need `make lint-markdown` and nothing else.

## Mental model

**Generated code is a build product that happens to be committed.** The `*_bpfel.go`, `*_bpfeb.go` and `*.o` files in the tree exist so that `go build` works without a clang toolchain, and so that consumers vendoring OBI as a library do not need one either. They are still outputs. Editing them is editing a build artifact — the next `make generate` discards the change.

`docker-generate` exists because the generated bytecode depends on the exact clang version and flags. Running generation in a pinned container image means two developers on different machines produce identical artifacts, so a regeneration does not show up as spurious diff noise in review.

## Structure / data flow

```
   bpf/<subsystem>/*.c   ──┐
   bpf/common/*.h          │   clang + bpf2go
   bpf/bpfcore/vmlinux.h  ─┘        │
                                     ▼
              pkg/internal/ebpf/<subsystem>/*_bpfel.go   (Go bindings)
              pkg/internal/ebpf/<subsystem>/*_bpfel.o    (bytecode, embedded)
                                     │
                                     ▼
                           go build  →  bin/obi
```

Target graph:

```
   make build
     ├─ docker-generate      run `make generate` inside the pinned generator image
     ├─ verify
     │    ├─ prereqs         → install-hooks, fetch-upstream-semconv
     │    ├─ go-mod-tidy
     │    ├─ lint            golangci-lint
     │    ├─ test            go test -short -race ./...  (with envtest assets)
     │    └─ license-header-check
     └─ compile              CGO_ENABLED=0 go build → bin/obi
```

## Key targets

| Target | Use it when |
|---|---|
| `make verify` | Default pre-PR check — lint, unit tests, tidy, license headers |
| `make build` | You need generation and compilation as well |
| `make generate` | You changed a `.c` file (incremental) |
| `make generate/all` | After a clean clone or `git clean` |
| `make docker-generate` | You want reproducible artifacts — the canonical path |
| `make compile` | Fast Go-only rebuild of `bin/obi` |
| `make compile-cache` | Build the `k8s-cache` binary |
| `make lint` / `make lint-fix` | Go lint iteration |
| `make lint-markdown` | Markdown-only changes |
| `make clang-format` / `make clang-tidy` | C formatting and static analysis |
| `make install-hooks` | Install the pre-commit hook once (also pulled in by `prereqs`) |
| `make test` | Unit tests only |
| `make test-privileged` | Tests requiring elevated capabilities |

## Where the build touches Go code

Two build-time values are injected into the binary rather than read from a file, via `-ldflags -X` in the `compile` target:

| What | Where |
|---|---|
| Version and revision variables | `pkg/buildinfo/buildinfo.go:9`, `pkg/buildinfo/buildinfo.go:10` |
| Where they are printed at startup | `cmd/obi/main.go:main` |

They default to `unset`, so a binary built with plain `go build` instead of `make compile` reports `Version=unset` in its startup banner — the quickest way to tell how a given binary was produced.

## Integration tests

Integration tests live in `internal/test/integration/` and are not part of `make verify`. Run a single one directly:

```bash
go test -v -run <TestName> -timeout 10m ./internal/test/integration/
```

There is also an OATS-based suite under `internal/test/oats/`, with its own Go modules per protocol (`redis`, `amqp`, `memcached`, a shared `harness`). Those modules — like the DWARF-offset probe modules under `configs/offsets/` — are separate `go.mod` files that are deliberately *not* part of the main module.

## Sharp edges

- **`make lint` reuses a shared golangci-lint cache across worktrees.** The Makefile comments that relative paths in `.golangci.yml` exclusions will not match from a worktree, and linting fails until you run `make lint-clean-cache`. This bites anyone using `git worktree`.
- **`make test` needs envtest assets.** It resolves `KUBEBUILDER_ASSETS` via `setup-envtest`; without network access on first run, the target fails for reasons unrelated to your change.
- **`prereqs` mutates your repo.** It installs the git hook and fetches upstream semantic conventions, so `make verify` is not a read-only operation.
- **`clang-tidy` deliberately skips directories.** `bpfcore`, `NOTICES` and `tests` are excluded; a lint-clean run does not mean every C file was checked.
- **Generation requires a container runtime.** `docker-generate` needs Docker or Podman running. Without it, fall back to `make generate` and accept toolchain-dependent output.
- **The repository has no Dockerfile-driven build for CI images.** Dependency pinning rules for the Dockerfiles that do exist are documented in [`devdocs/dependency-integrity-policy.md`](../../../devdocs/dependency-integrity-policy.md).

## Contribution rules that gate a change

Beyond the mechanical targets, [`AGENTS.md`](../../../AGENTS.md) and [`CONTRIBUTING.md`](../../../CONTRIBUTING.md) impose constraints that reviewers enforce:

- Keep changes minimal and scoped; no unrelated edits, formatting churn, or cleanup.
- Do not introduce new implementations when equivalent functionality already exists.
- eBPF maps not explicitly pinned for external use default to `OBI_PIN_INTERNAL`.
- Use `SCRATCH_MEM` and friends instead of ad-hoc temporary buffers.
- Target kernel 5.8+ with BTF (plus RHEL-family 4.18 with backports); gate anything newer behind a runtime check.
- This is a Linux Foundation project with its own [`AI-POLICY.md`](../../../AI-POLICY.md) — generative-AI use above trivial autocomplete must be disclosed, and you are accountable for reviewing what you submit.
